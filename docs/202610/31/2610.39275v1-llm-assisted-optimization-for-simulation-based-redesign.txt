# LLM-Assisted Optimization for Simulation-Based Redesign 

Engineering design frequently involves redesigning a prior solution to adapt to changes in context, such as material prices or system requirements. Redesign often leverages sim-ulators too complex and/or computationally intensive for traditional numerical solvers, which lack engineering knowledge and context, to ensure global solution quality. Large language models (LLMs) can interpret semantic information, including engineering knowl-edge about the system and changes in context, to help guide search, and recent studies have shown that incorporating this knowledge into optimization can improve search perfor-mance. However, how best to combine LLMs with numerical solvers in redesign remains unclear. We develop and test an integrated LLM-optimization approach for redesign and compare three methods for leveraging LLMs (warm start, variable fixing and ReAct) and four black-box solvers (Bayesian optimization, genetic algorithms, mesh adaptive direct search and random search) on an electric vehicle battery pack cost minimization case study across four types of redesign scenarios. We find that the integrated approach can match feasible design discovery of the numerical-solver baselines with 80% fewer simu-lator evaluations while tripling the fraction of runs that find near-optimal solutions. We find that the best LLM-solver integration approach and the way the prior solution is lever-aged depend on the structure of the design requirement change, and that the benefit of increasing LLM model size grows with the extent to which the LLM controls the search. These results show clear potential for LLMs in redesign tasks for guiding or replacing numerical solvers. Keywords: Artificial Intelligence, Design Optimization, Energy Systems Design, Machine Learning, Simulation-Based Design 

1 Introduction 

In practical engineering design, developing a satisfactory prod-uct often requires repeated cycles of evaluation and modification [1]. As this process continues, changes in requirements, subsystem interfaces, material availability, or system integration can make an existing design unsuitable for the updated design context. Adapting an existing design to such changes is commonly treated as redesign, and this redesign effort can consume substantial engineering ca-pacity, development time, and cost [2–4]. In the automotive in-dustry, for example, more than 1,000 engineering change orders per month and process costs of approximately 20,000–50,000 Eu-ros per change have been reported at a major manufacturer [5]. Individual engineering changes can also require several weeks or months to resolve [2]. Reducing the effort required for redesign can therefore shorten an important and costly part of the overall engineering design process. One way to reduce this redesign effort is to use computational methods to automate the evaluation and improvement of candidate designs [6–9]. In many practical optimization tasks, however, the relationship between design variables and design performance can-not be written in a compact analytical form that is convenient for direct optimization. Engineers therefore evaluate candidate designs through simulation, where physical models, numerical iterations, empirical correlations, calibrated parameters, and lookup struc-tures may all contribute to the predicted performance [10, 11]. When simulation is placed inside an optimization loop, the re-sulting process is commonly described as simulation-based design optimization. Because the internal relationships of the simulator can be difficult or impractical to expose directly to the optimizer, these problems are often treated as black-box optimization prob-lems even when much of the underlying engineering physics is known [10, 12]. When the design context later changes while a previous design remains available, the same setting becomes a

reoptimization problem in which information from the previous design may still be useful. Solving this black-box reoptimization problem can require many additional simulator evaluations. Numerical methods such as Bayesian optimization, evolutionary algorithms, and direct search address this problem by using information collected from previous evaluations to guide subsequent search [11–13]. Their search deci-sions are therefore driven primarily by numerical observations col-lected during optimization, and previous evaluations can become obsolete and/or misleading depending on the changes in design context for redesign. But the redesign context provides another source of information before many of these evaluations are per-formed. Engineers often know what changed in the design context, which physical relationships are relevant to that change, and which parts of the previous design are likely to remain useful. Using this semantic engineering information during reoptimization could therefore provide information that is not captured in the numerical evaluation history alone. Large language models (LLMs) provide a possible way to incorporate semantic engineering information into optimization. LLM agents can interpret textual problem descriptions, generate structured actions, and interact with external computational tools [14, 15]. Recent studies have explored these capabilities in op-timization: LLMs have been used for iterative solution genera-tion, warm starting, and context-informed candidate selection to improve numerical optimization [16, 17]. Hybrid optimization methods have also combined LLM-derived prior knowledge with Bayesian optimization, motivating the separation of semantic prior reasoning from numerical search [18, 19]. Similar capabilities have been explored in engineering design: LLM agents have been used to coordinate engineering analysis and simulation tools and to improve designs through repeated simula-tor feedback [20, 21]. Recent studies have further examined the effects of model scale and agent architecture in LLM-based engi-neering design workflows [22–26]. Together, these studies show

[27] showed that feedback-driven LLM search and LLM-generated warm starts can exhibit different strengths relative to conventional numerical optimization when the design context changes. However, it remains unclear how seman-tic engineering information about an existing design and a changed design context should be used during simulator-driven reoptimiza-tion. This question can be studied by placing semantic guidance at different stages of the reoptimization process. Existing reoptimiza-tion methods commonly reuse information from a previous solu-tion through mechanisms such as warm starting or variable fixing [28–31]. Recently, Ye et al. [32] introduced LLM-guided reopti-mization for explicit mathematical optimization models, where the LLM translates changed requirements into structured model up-dates and selects the reoptimization strategy that the solver uses. In simulator-driven engineering design, however, the governing en-gineering relationships may instead remain embedded inside an ex-ternal simulator and unavailable for direct modification. Semantic information can still influence the search by guiding the initial de-signs, identifying parts of the reference design that should be kept, or interpreting simulator feedback during iterative search. These possibilities motivate the three LLM roles considered in this study (warm starting, variable fixing, and ReAct search). We study these roles within a framework that we call Workflows for AI-Facilitated Engineering Redesign (WAFER). To compare these roles under different redesign conditions, we consider a case study of lithium ion battery pack design for elec-tric vehicles. Battery designs can require revision when material prices and supply conditions change [33], when the physical space available to the pack changes [34], or when vehicle level require-ments are revised, such as when a pack designed for one vehicle model is redesigned for use in another model, model year, or trim level. Fast charging introduces another redesign condition because charging performance depends on electrochemical transport and polarization within the cell [35, 36]. These changes require differ-ent types of engineering information and therefore provide a useful setting for examining whether the value of semantic guidance de-pends on the redesign scenario. We evaluate the resulting design problems using the Battery Performance and Cost (BatPaC) model developed by Argonne National Laboratory [37] and use the model as an external simulator throughout the study. Using this common testbed, we study how the placement of LLM guidance affects engineering redesign performance, and Fig. 1 summarizes the framework. Starting from a common reference design, we construct four redesign scenarios involving changes to material cost, available pack space, fast charging, and vehicle energy requirements. We then compare warm starting, variable fixing, and ReAct with numerical optimization under a common simulator evaluation budget, using three language model sizes. Based on this framework, we address three research ques-tions. (1) To what extent does LLM-assisted reoptimization improve feasible-design discovery and final design quality relative to conventional black-box optimization under a fixed simulator-evaluation budget? (2) What characteristics of a redesign scenario determine which LLM-assisted methods are most effective, and what mecha-nisms explain differences across scenarios? (3) How does the benefit of increased LLM size relate to the degree of control it exerts on search, and how does that benefit compare to cost in inference time and token use? This work makes three main contributions to LLM-assisted engi-neering redesign. First, we show that LLM-assisted reoptimization reaches a feasible redesign in far fewer simulator evaluations and ends at a lower cost than cold-start and reference-warm numeri-cal optimization under a common simulation budget. 2 Battery-Pack Redesign Problem 

In this section, we define the electric vehicle (EV) battery-pack design problem used as the redesign testbed in this study. Battery-pack design couples decisions across the cell, module, and pack levels through electrochemical, electrical, and packaging relation-ships, while the design conditions for the pack can change as the vehicle design progresses. We formulate a common reference opti-mization problem, obtain the reference design used throughout the study, and construct four redesign scenarios that change distinct aspects of the reference condition.

S2: Change in space constraints. S2 represents redesign caused by a reduction in the physical space allocated to the battery within the vehicle. Vehicle programs also develop many subsys-tems in parallel, so a revision elsewhere in the vehicle, such as a change to the door or body structure, can reduce the space left for the pack after the battery layout has already been set [34]. Fol-lowing the 3beLiEVe project, which sets a maximum battery-pack size of 1500 × 1100 × 150 mm for segment A/B battery-electric vehicles [50], we reduce the allowable pack width from 1500 to 1100 mm. Because the reference design has a width of 1400 mm, this change directly invalidates the existing layout and requires a geometry-driven redesign of the module and pack topology. 

S3: Change in charging requirements. S3 introduces a faster charging requirement that activates additional thickness-dependent feasibility in BatPaC. Charging time is a purchase-relevant vehi-cle attribute, and shortening it constrains cell design because the achievable rate depends on transport and polarization within the electrode [35]. The reference condition uses a 60-min recharge re-quirement, and the target condition reduces it to 30 min as in prior BatPaC-based battery design studies [39]. For the target prob-lem, BatPaC computes a candidate-specific maximum allowable cathode thickness. The simulator returns the feasibility outcome together with the margin to that limit, and this margin enters the penalized objective as a constraint violation. 

S4: Change in energy requirements. S4 represents redesign for a vehicle class requiring substantially greater battery energy. The target energy is increased from 84 to 130 kWh, which moves the problem from the scale of the IONIQ 5 reference vehicle toward that of the extended-range Ford F-150 Lightning [51]. Because a larger battery also requires additional packaging space, the max-imum pack length and width are relaxed to 2700 and 1650 mm, respectively. Reusing the reference topology at the 130-kWh target produces a cell capacity of approximately 161 Ah, which exceeds the 120-Ah limit. The target problem therefore raises cell capacity while also requiring a redistribution of the pack topology. We ensured that every target problem contains feasible designs by evaluating the preliminary grid of Appendix A under each tar-get condition, reported in Appendix F. These reference evaluations were used only for problem construction and subsequent interpreta-tion and were not provided to the language models or the numerical optimizers during the main experiments.

3.3 Semantic Information and Language Models. The semantic-information treatment controls how much engineering knowledge is provided beyond the numerical optimization formu-lation. In L1, the model receives the design variables and bounds, reference design, redesign requirements, objective, and constraint definitions. In L2, this information is supplemented with compact engineering relationships relevant to battery redesign, including chemistry-dependent cost and energy tradeoffs, electrode-thickness effects, voltage and current relationships, and geometric conse-quences of pack topology. We wrote these relationships from the BatPaC manual [37] and basic electrochemical principles so that they cover the changes in the four redesign scenarios. Both levels are placed in the user message that accompanies a fixed system message. The comparison therefore tests whether explicit engi-neering relationships provide useful guidance beyond the problem definition alone. Appendix B reproduces the complete prompts. We use Qwen3.5 as the language model, at the 4B, 9B, and 27B parameter sizes with the released bfloat16 weights and no quanti-zation, and we do not perform any task-specific fine-tuning [52]. Qwen3.5 supports explicit reasoning and tool calling, which are needed to interpret engineering information and interact with the external simulator during redesign. The publicly available model weights also allow local deployment, providing control over model scale and inference infrastructure while avoiding the need to trans-mit potentially sensitive engineering information to a hosted model service. Keeping the same model family and prompting framework across the three sizes lets us attribute the difference to model scale. Model outputs are converted to structured redesign actions and validated before simulator evaluation. Exact prompts, sampling settings, and output schemas are provided in Appendix B. Because the L2 treatment relies on the model correctly inter-preting the supplied engineering information, we separately tested its comprehensibility using Qwen3.5-4B, the smallest model con-sidered. Across 12 tests spanning all four redesign scenarios, the model recovered and interpreted the main L2 engineering relation-ships in nearly all cases and consistently distinguished quantities that require BatPaC evaluation from information available in the prompt. Appendix C discusses the test in detail. 

3.4 LLM Integration Strategies. The three LLM strategies represent different ways in which semantic information can influ-ence redesign. Warm starting (WS) uses the LLM before numer-ical optimization to propose three initial designs. These designs are evaluated by BatPaC and used to initialize the downstream optimizer, testing whether semantic guidance can provide starting points that either lie in promising regions of the redesigned search space or help the optimizer learn the behavior of the objective. Variable fixing (VF) instead uses the LLM to determine which variables of the reference design should remain fixed and which should be released for optimization. The downstream optimizer then searches only the variables that remain free, starting from a random point in that reduced space. This strategy tests whether engineering knowledge can reduce the effective search dimension by preserving design decisions that remain useful after the redesign condition changes, and whether that reduction improves optimiza-tion performance. ReAct uses semantic guidance throughout the search and fol-lows the reasoning-and-acting loop introduced for language model agents [14], in which reasoning steps and actions alternate. The model states its reasoning, proposes a design, and receives the ob-jective and constraint values of the design and its feasibility from BatPaC as the observation for that step. The action and obser-vation of every earlier step are carried forward in the prompt, so each new candidate is chosen based on the accumulated record. ReAct therefore tests whether engineering judgment based on the trajectory of evaluated designs and simulator feedback improves the search at each step. 

3.5 Numerical Search and Reference Conditions. Black-box optimizers choose the next design from function evaluations alone. They are commonly divided into model-based methods, which fit a surrogate of the objective, and direct-search meth-ods, which compare function values directly [11, 12]. For expen-sive black-box problems, Bayesian optimization and evolutionary 

Journal of Mechanical Design PREPRINT FOR REVIEW / 5 search are regarded as the two principal families [53]. We therefore pair WS and VF with four methods that cover both classifications: Bayesian optimization (BO) as a model-based method, a mixed-variable genetic algorithm (GA) as an evolutionary method, mesh adaptive direct search (MADS) as a direct-search method, and ran-dom search as a nonadaptive reference that uses no feedback [54]. BO uses a probabilistic surrogate model and an acquisition func-tion to guide evaluations of expensive black-box objectives [13, 55]. We implement it with the Ax adaptive experimentation framework, which supports mixed continuous and discrete search spaces [56]. The GA evolves a population of designs by recombining promising candidates and mutating them to explore nearby designs. Because the battery problem combines categorical, continuous, and integer variables, we implement the GA with the mixed-variable algorithm of pymoo [57]. MADS is a model-free direct-search approach de-veloped for constrained black-box optimization and widely applied to simulation-based engineering problems [58, 59]. All four optimizers receive the same penalized scalar objec-tive. When a design is feasible, the objective is its BatPaC cost. Otherwise, a fixed penalty and a term proportional to the total nor-malized constraint violation are added to the cost. This keeps the information available to the four optimizers identical. We addi-tionally evaluate non-LLM numerical baselines using each of the same four optimization methods. In the cold numerical condition, the optimizer begins from de-signs sampled uniformly at random from the design domain with-out information from the reference design. In the reference-warm condition, the reference design xREF is included in the numerical initialization. Appendix D gives the exact penalty, the optimizer settings, the initialization procedures, and the software configura-tions. 

3.6 Evaluation and Statistical Analysis. Because ReAct car-ries its interaction history in the prompt, its context grows with every accepted evaluation and with every rejected proposal. We limited the budget to 20 evaluations so that this history stays within the 32,768-token context window of the three model sizes, and no run in this study terminated because of context length. We evaluate redesign effectiveness by how often and how early a method finds a feasible design and by how low a cost it reaches. Feasible-design discovery records whether a method identifies at least one design satisfying all redesign constraints. Search effi-ciency is measured by the accepted evaluation index of the first feasible design. Design quality is measured by the lowest feasi-ble BatPaC cost obtained within the 20-evaluation budget. We also measure computational effort by LLM inference time and to-ken use, and we report the number of runs that terminate without producing a usable decision. Neither the numerical optimizers nor the language model is de-terministic, so a single run of a configuration provides noisy infor-mation about that configuration. We therefore repeat every config-uration over 50 seeds and compare distributions of our performance metrics. We compare feasible discovery and near-best attainment be-tween configurations with a two-sided Fisher exact test [60] and adjust the 𝑝 -values with the Holm procedure within each fam-ily defined by one scenario, one strategy, and one metric [61]. Section 4.1 states how the configurations are paired. Proportions shown in the figures are reported with 95% Wilson intervals [62]. The association between the VF release and WS move probabil-ities in Sec. 4.2 is measured with the Spearman rank correlation [63]. For proportions pooled over configurations, the Wilson in-tervals reflect sampling variation among runs and do not include differences between configurations.

4.2.1 Variable fixing works best when the necessary redesign involves only a few variables. The strength of VF is that it reduces the number of variables and thereby makes the downstream op-timization more efficient. We write a VF decision as a mask of five letters, one per design variable in the order (𝑥 C, 𝑥 T, 𝑥 S, 𝑥 M, 𝑥 R),where R (released) marks a variable that is released to the optimizer and F (fixed) marks a variable that is fixed at its reference value. RRRRR therefore releases everything and RFFFF releases only the chemistry. Figure 6 shows the outcome of the runs grouped by the mask that the language model selected in S1 and S3. For each mask selected in at least 20 runs, the bars give the fraction of those runs that reached a feasible design and the fraction that reached a gap of 2% or less, pooled over model sizes and optimizers. The masks are ordered so that fewer variables are released from left to right. In both scenarios, the fraction of runs that reach feasibility rises sharply as fewer variables are released. The RRRRR mask in S1 releases every variable and only 133 of the 491 runs that selected it 

8 / PREPRINT FOR REVIEW Transactions of the ASME reached feasibility, while every one of the 435 runs on the RRFFF mask and every one of the 118 runs on the RFFFF mask reached feasibility. S3 shows the same pattern, where 39 of 204 runs on RRRRR reached feasibility against 499 of 509 runs on RRFFF. In S3 the near-best attainment follows the same ordering, rising from 3 of the 204 runs on RRRRR to 387 of the 509 runs on RRFFF. This suggests that reducing the search space, and thereby making the search more efficient, is the main mechanism by which VF improves performance in the problems where VF works. VF works well in S3 because the variable that must change is easy to identify. The best S3 design differs from the refer-ence design only in 𝑥 T, and the shorter recharge time constrains the electrode thickness directly. Every model size released 𝑥 T in 100% of its valid S3 decisions. However, in S2 and S4, identify-ing the required variables depends on the electrode area together with geometric quantities such as 𝑥 M and 𝑥 R. The electrode area is determined by the nonlinear electrochemical calculation inside BatPaC. These quantities are directly connected to the design con-dition change in those two scenarios, which makes the identifica-tion problem much harder. In both of them, every run that fixed a required variable failed to reach feasibility, since an incorrect fixing decision leaves no feasible design in the remaining subspace and the downstream optimizer searches only that subspace. Table 9(a) in Appendix F reports the mask analysis for S2 and S4. S2 is difficult even when the correct variables are released, be-cause its feasible region is narrow. Among the masks that fix at least one variable, the one selected most often in S2 is FFFRR, which releases only 𝑥 M and 𝑥 R. Inside that subspace only the cell at 𝑥 R = 3 and 𝑥 M = 3 contains feasible evaluations, and all 50 evaluations in that cell are feasible. FFFRR is nevertheless the second-best of the available S2 masks, with a run-level feasibility of 21%. In S4 the most frequent mask FRRRR reaches 42%, and its feasible evaluations concentrate at 𝑥 R = 4, with the highest fea-sible fraction of 68% at 𝑥 M = 4. However, feasible discovery inside these narrow subspaces also depends on the downstream optimizer. In the FFFRR subspace of S2, MADS reaches 69%, against 7% for GA, the second-best optimizer. Figure 12 and Table 9(b) in Appendix F give the details. Taken together, VF shows a clear advantage by shrinking the search space when the variables that must change are easy to iden-tify. When it is unclear which variables should be left open, an incorrectly fixed variable removes feasibility from the remaining subspace and the downstream optimizer cannot recover it. How-ever, even when the feasible domain is narrow and complex, VF can still perform well when it is paired with a suitable optimizer such as MADS. It is important to note that, had more iterations been permitted, more released variables may have allowed the solver to reach a better solution. With a limited iteration budget, variable fixing can help use the limited available compute to concentrate search effort in a subspace that can produce greater benefits per iteration.

4.4 Implications. For practical redesign problems, the three WAFER strategies serve different functions. Each strategy applies the language model at a different point of the search, and the structure of the redesign problem determines which approach is most effective. Variable fixing changes the dimension of the search. Warm starting directs the search toward promising regions, and it performs consistently across all four scenarios. ReAct can change the search strategy at every step and is able to continue improving the objective after feasibility has been secured. This suggests a simple selection rule. When the requirement change maps onto one or two design variables that can be identified with confidence, variable fixing gives the largest improvement at the lowest computational cost. When the promising region can be described but the responsible variables cannot be isolated, warm starting is the more reliable choice. When the objective still has room to improve after feasibility is reached, ReAct can be effective, and a larger ReAct model is preferable when the inference cost is not the main concern. Importantly, a larger iteration budget could change these observed trends, since a larger iteration budget can affect the ability of numerical solvers to identify feasible solutions and approach global optimality. 

5 Conclusions 

We compared three ways of integrating a large language model inside a simulator-driven redesign loop (warm starting, variable fixing, and ReAct search) against cold-start and reference-warm numerical optimization. The comparison used an electric vehicle battery-pack design problem evaluated with the BatPaC simulator under four redesign scenarios that change material cost, packaging space, charging requirement, and required energy. The key findings of this study are as follows. (1) Language model guidance reaches a feasible redesign in fewer simulator evaluations and ends at a lower cost than the numerical baselines under the same budget. The gain is largest in the scenarios where the reference design becomes infeasible and the feasible region is difficult to locate from function values alone. (2) The most effective LLM-assisted method differs across re-design scenarios. The outcome is decided by the way each method uses the reference design, so the structure of the requirement change determines which method to apply. (3) The benefit of a larger language model grows with the extent to which the model controls the search. It was largest for ReAct and noisy for warm starting and variable fixing, which use a numerical optimizer for the remaining budget. This study has several limitations. The first is the scope of the testbed. We used one simulator and one product family. Applying the same comparison to a different simulator and to a design prob-lem whose variables are coupled in a different way would show whether the three methods show the same pattern. Constraint han-dling in the numerical optimizers may also vary by implementa-tion, and a different choice could change how they compare with the LLM-assisted methods. The second is the measure of search effort. We focus on a budget of simulator evaluations, which is the appropriate unit when a single simulation is far more expensive than the reasoning or search algorithm compute needed to determine which points to simulate. In our setting the median BatPaC evaluation took 6.5 seconds while a ReAct run required several hundred seconds of inference, so the two costs are not separated by the margin that this choice assumes. Repeating the comparison on a practical engineering simulator that takes hours per evaluation would show how the methods compare when the simulation cost dominates. The third is the language model itself. We used only Qwen3.5 at three sizes, and frontier models may have stronger perfor-mance. Other model families including frontier models, or frame-works such as fine-tuning or retrieval-augmented generation, could change the behavior of the three methods. Overall, our results suggest that LLMs have strong potential to provide effective assistance in simulation-based engineering re-design efforts by augmenting or even replacing numerical solvers. Our experiments begin to identify the types of redesign context and requirement shifts on which each LLM-based approach performs best. More research comparing LLM-assisted redesign across a range of engineering domains, LLM models, integration ap-proaches, and numerical solvers could help more fully establish best practices for LLM use in redesign.

Appendix B: Prompts and Model Configuration 

Each prompt consists of a fixed system message and a structured user message. The user message contains the redesign problem def-inition, the reference design and its evaluated reference-condition result, the change from the reference to the redesign condition, the L1 or L2 semantic information, the strategy-specific instructions, and the required output format. The system message is identical under L1 and L2. All three strategies use the same sampling settings. Requests are sent to a local vLLM endpoint with an OpenAI-compatible chat interface at temperature 0.7, top-𝑝 0.8, and a limit of 4096 generated tokens, with a context length of 32,768 tokens. The generation seed equals the run index. Structured output is enforced by the endpoint using a strict JSON schema. A response is rejected without consuming the simulator budget if it cannot be parsed, violates the schema, repeats an already evaluated candidate, or falls outside the variable bounds. In warm starting and variable fixing, a rejected response triggers one retry with the rejected output, the validation error, and the information needed to correct it, such as the chemistry-specific thickness bounds. A run whose retry also fails ends without a decision. In ReAct, a response that cannot be parsed or violates the schema triggers one repair request. Arepeated or out-of-bounds candidate is instead returned to the agent as the observation for its next step. ReAct additionally allows at most 60 agent steps per run. The complete system prompts, strategy instructions, optimizer-specific initialization instructions, ReAct action instructions, JSON output schemas, and the Level 1 and Level 2 semantic texts are reproduced verbatim in the code repository (https://github.com/C hani-song/WAFER).
